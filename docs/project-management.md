## 任务队列与保护

任务页的「标注 / Label」使用项目采样；点击某一行任务使用原数据列表浏览。输入筛选或修改顺序后的请求完成前，标注按钮禁用，避免使用旧条件启动队列。返回较早任务后提交或跳过会继续到已有的下一条访问记录，不会漏过该记录。

队列请求通过 GET query 传递筛选、顺序和已访问 ID，保留 Django 的项目采样语义。空项目及本地不支持的标注配置仍可管理，但无法在桌面编辑不支持的标注类型。随机采样不保证多次抽样必然出现特定排列，完成/跳过资格由 Django 决定。

最近访问记录只保存项目 ID；密码、Token、Cookie 不写入此记录。

## 验证与复现

```powershell
.\build.ps1 -Test
.\tests\run-project-live.ps1
.\tests\run-account-live.ps1
.\build.ps1 -Deploy
```

`run-project-live.ps1` 创建独立 QA 用户、组织、项目和两个数据视图，运行原生界面与 API 流程，直接检查数据库，再清理自己的数据。不使用或修改已有用户项目。凭据随机生成，仅放在测试进程环境中。

本次验证：

- MSVC 构建及 language、document、api、native_ui、live_django 五组 CTest 全部通过；默认 CTest 不启用真实服务器写测试，真实联调由下列隔离脚本单独执行。
- 项目隔离联调通过：空项目创建/卡片删除、设置保存、导入三张图片、顺序及随机采样、矩形保存、历史中提交后继续、跳过、重置缓存、丢弃标签页、搜索与最近访问；无 QML 警告。
- 数据库直接核验通过：测试项目的两个视图已删除，三条任务和已保存标注保留，颜色与随机采样策略正确。
- 账户与组织隔离回归通过；两套临时组织均已自动清理，未修改已有用户项目。
- 中英文及 1060×700 窗口截图已检查；常规设置滚动到底后，通过实际鼠标点击「保存」完成写入。
- `build.ps1 -Deploy` 通过；部署目录使用 Windows 平台插件启动退出码为 0，成功生成登录页截图，无启动诊断错误。
- 回归测试覆盖创建动画开始前清除旧模板、项目列表后续页失败保留原列表、维护失败保留筛选、采样历史中的提交/跳过以及重新启动队列失败后保留历史。
